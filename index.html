01

The whole protocol in one exchange

x402 revives HTTP status code 402, reserved since the 1990s and never specified. A paid request is two round trips: the server quotes a price in a header, the client signs a payment authorization offline, and the retry carries it. No account, no API key, no session.

wire capture: buying one API responseamount: 0.01 USDC, network: arbitrum
  1. 1. Client asksagent, browser, script
    > GET /api/insight HTTP/1.1
> Host: api.example.com
  2. 2. Server quotesresource server
    < HTTP/1.1 402 Payment Required
< payment-required: eyJ4NDAyVmVyc2lvbiI6Mi4uLg  (base64 JSON)
  decoded: { accepts: [{ scheme: "exact", network: "eip155:42161",
             asset: "0xaf88...5831", amount: "10000", payTo: "0xSeller" }] }
  3. 3. Client payssigns offline, retries
    > GET /api/insight HTTP/1.1
> payment: eyJzaWduYXR1cmUiOiIweDMuLi4  (base64 signed EIP-3009 auth)
  4. 4. Server settlesfacilitator verifies, submits tx, gas on the house
    < HTTP/1.1 200 OK
< payment-response: eyJzdWNjZXNzIjp0cnVlLi4u  (decoded: { success: true, transaction: "0xTxHash" })
<
< { "insight": "the thing you paid for" }

The client never sends an on-chain transaction and never spends gas. It signs a message; the settlement transaction is submitted by the facilitator.

/api/insight is this guide's example route, not part of the protocol. x402 standardizes headers and payloads only; any HTTP route on any path can be priced.

Steps 5, 6 and 8 are in-process calls when the facilitator is embedded in the server, or HTTPS calls when it is hosted. Either way the wire between agent and API is identical.

02

The four-layer stack

Each layer answers a different question. x402 is the protocol layer; it borrows the money and settlement layers from Ethereum, and delegates the permission question upward.

L4AuthorizationShould this agent spend at all? AP2 mandates: verifiable credentials signed by a human ("up to $50, on travel, until Friday").
L3ProtocolHow does a payment ride an HTTP request? x402: the 402 challenge, headers, schemes, and the facilitator role.
L2Settlement primitiveWhat moves the token? EIP-3009 transferWithAuthorization, or Permit2 for tokens without it. Signed offline, submitted by anyone.
L1MoneyA stablecoin on an EVM chain. Usually USDC: 6 decimals, native EIP-3009 support on every chain Circle deploys to.
03

Three roles, three jobs

Buyer side

Client

Whoever wants the resource: an AI agent, a script, a browser wallet.

  • Holds the token, nothing else
  • Signs the payment authorization offline
  • Retries the request with the payment header
  • Never touches gas
Seller side

Resource server

The API being paid for. Prices routes and delegates payment handling to middleware.

  • Declares price, token, network, payTo per route
  • Challenges unpaid requests with 402
  • Runs the handler only after verification
  • Returns the settlement receipt header
Infrastructure

Facilitator

The courier. Verifies signed authorizations and submits the settlement transaction.

  • verify: signature, amount, expiry, balance
  • settle: submits the tx, pays its gas
  • getSupported: advertises schemes and networks
  • Never custodies funds; can only execute the exact signed transfer or nothing
04

HTTP surface

All protocol data rides in three headers as base64-encoded JSON. Response bodies stay yours.

HeaderDirectionCarries
payment-requiredserver to client, on 402The challenge: accepts[] with scheme, network (CAIP-2), asset address, atomic amount, payTo, timeout
paymentclient to server, on retryThe signed payment payload for one of the accepted options
payment-responseserver to client, on 200The settlement receipt: success, transaction (tx hash), network, payer
Gotcha: the 402 response body is {}. Everything lives in the header. Decode with decodePaymentRequiredHeader and decodePaymentResponseHeader from @x402/core/http, never by hand.
Amounts are atomic and stringly typed. "10000" means 0.01 USDC (6 decimals). Parse to bigint, never to a float.
05

Payment schemes

SchemeModelUse when
exactFixed price per request, settled in fullPay-per-call APIs, downloads, one-shot purchases. The default; start here.
uptoClient authorizes a ceiling, server settles actual usageMetered billing: tokens generated, compute time, partial settlement
batch-settlementMany small payments settled together on-chainHigh-frequency micropayments where per-tx gas would dominate
auth-captureAuthorize now, capture laterReservation-style flows, familiar from card processing

All four ship in @x402/evm v2. Sellers can offer several options in one challenge via the accepts array.

Networks and tokens

x402 v2 identifies networks with CAIP-2 ids: namespace:reference. For EVM chains that is eip155:<chainId>. Default stablecoins per network ship in @x402/evm, so sellers can price in dollar strings like "$0.01".

Settlement primitives: who signs what

EIP-3009Permit2
What it istransferWithAuthorization: transfer authorized by an offline signature, built into the token contractUniswap's universal approval contract; a signature spends a pre-granted allowance
Token supportMust be implemented by the token. USDC has it everywhereAny ERC-20, after a one-time on-chain approval to the Permit2 contract

The gasless trick in one line: the buyer signs a message; the facilitator submits the transaction and pays the gas. That is why an agent wallet needs USDC and nothing else.
08

Facilitators: hosted or your own

Hosted

Someone runs it for you

Point your middleware at a URL. Coinbase and the x402 Foundation operate public ones.

  • Zero wallets to fund or monitor
  • Limited network coverage (check /supported)
  • A third party in your request path
Self-hosted

Run it in your own process

Implement verify / settle / getSupported against the chain directly, signing with your own wallet.

  • Works on any EVM chain viem knows
  • No external dependency, no coverage gaps
  • Your settlement wallet needs native gas
  • Prebuilt: @mariano-aguero/x402-self-facilitator

Trust model either way: the facilitator can execute the exact signed transfer or refuse to. It cannot redirect funds, change amounts, or spend anything the buyer did not sign.

09

The layer above: AP2 and mandates

x402 answers how an agent pays. It does not answer whether the agent should. That is the authorization layer, and the emerging standard there is AP2 (Agent Payments Protocol, led by Google with 60+ partners).

The core object is the mandate: a verifiable credential signed by the human principal that scopes what the agent may spend. An intent mandate captures the ask ("book me a flight under $300"); a cart mandate pins the exact purchase before payment. Payment execution then happens over rails like x402.

Practical hierarchy of guards today: client-side checks (allowlists, balance caps) are the floor; signed mandates verified by the seller are the standard forming; spend policies enforced on-chain by the wallet itself (smart accounts) are the strongest, since not even a compromised agent can exceed them.

11

Minimum viable seller and buyer

Seller: a Hono route priced at one cent, settling on Arbitrum with a self-hosted facilitator.

import { paymentMiddlewareFromConfig } from "@x402/hono";
import { ExactEvmScheme } from "@x402/evm/exact/server";
import { createSelfFacilitator } from "@mariano-aguero/x402-self-facilitator";

const facilitator = createSelfFacilitator({ chain: arbitrum, account: sellerAccount });

app.use("/api/insight", paymentMiddlewareFromConfig(
  { "GET /api/insight": { accepts: {
      scheme: "exact", network: "eip155:42161",
      payTo: sellerAccount.address, price: "$0.01" } } },
  facilitator,
  [{ network: "eip155:42161", server: new ExactEvmScheme() }],
));

Buyer: a Claude agent whose fetch tool pays challenges from its own wallet.

import Anthropic from "@anthropic-ai/sdk";
import { createX402Tools } from "@mariano-aguero/anthropic-x402-tools";

const { tools, payments } = createX402Tools({
  account: agentAccount,           // holds USDC, never needs gas
  chain: arbitrum,
  token: { address: "0xaf88d065e77c8cC2239327C5EDb3A432268e5831" },
  apiBase: "https://api.example.com",
});

const message = await new Anthropic().beta.messages.toolRunner({
  model: "claude-opus-5", max_tokens: 16000, tools,
  messages: [{ role: "user", content: "Buy me one premium insight." }],
});
// payments[] now holds { url, amount, txHash } per settled payment
